ENGINEERING GUIDELINES (v1.4)

## Branching
Trunk-based development with short-lived branches named feature/ATL-<id>-<slug>. Hotfix branches use hotfix/ATL-<id>-<slug>.

## Pull Requests
Every pull request requires 2 approvals before merge. (Version 1.3 required 1 approval; this was raised after the August 2024 outage.) CI must pass. New code must have at least 80 percent unit test coverage.

## Commits
Use conventional commit messages, for example fix(catalog): correct TTL handling.

## Database Migrations
All migrations must follow the expand/contract pattern so that the previous application version keeps working while a rollout is in progress. Destructive changes (dropping or renaming columns) must be split across two releases.

## Tooling
Python 3.11, ruff for linting, black for formatting.

## Releases
No production deployments on Fridays except approved hotfixes.
